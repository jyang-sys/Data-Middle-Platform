# 销售人员与店铺默认负责人

独立页面 `/settings/people` 使用服务端 D1 中的真实业务配置，不载入演示人员。维护员工唯一编号（忽略大小写判重、创建后不可修改）、姓名、所属销售小组、在职/停用状态；人员不做物理删除。支持按姓名/编号、小组和状态筛选。

小组与 `/settings/shops` 共用。店铺新增默认销售负责人，候选人为同组在职人员。店铺改变所属小组后，不匹配的负责人清空。人员调组或停用时显示将受影响的店铺数量；保存时一次提交人员及相关店铺默认负责人清空，店铺销售小组保留。未分组人员可以建档，但不能指定为店铺负责人。

人员和归属共用 shop_settings 的版本、认证及原子条件更新，避免人员变更与店铺保存相互覆盖。兼容旧客户端未传 employees 的保存请求，保留已有人员；旧配置缺少 employees 时读取为空列表。无需修改已应用的数据库迁移。

本次维护基础资料与默认负责人，不回写 Base，也不修改历史订单或演示业绩。Base 负责人附加字段、SKU 负责人规则和新订单自动落归属仍为后续工作。

验证：`node scripts/check-people-settings.mjs` 检查唯一编号、稳定编号、同组校验、停用、调组及清空关联、旧客户端兼容和版本冲突。浏览器检查新增、店铺负责人候选范围、跨浏览器读取、停用影响提示及清空、重复编号、移动端和导航入口；既有店铺、来源同步、Base Worker 与扩展演示校验通过。
