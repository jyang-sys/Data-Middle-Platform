# 店铺归属设置

私有测试 Site 的 `/settings/shops` 为独立设置页面，销售总览侧栏提供入口。店铺来源读取最近一次 Base 同步的 `getOrderSources` 数据，按来源类型和来源 ID 唯一识别，名称变化不丢失配置。

支持新增、重命名销售小组；逐店或批量分配、清空默认销售小组；按来源、归属状态和名称/ID 搜索。编辑为草稿，点击保存后统一生效；离开页面时提示未保存修改。

配置使用 Sites 的 D1 `DB` 绑定持久保存，跨浏览器共享；按测试数据源密钥哈希隔离，不使用浏览器存储或缓存保存业务配置。重新部署不重置配置；更换数据源密钥会进入新的隔离范围。来源刷新不会改写归属。失效来源保留历史配置并只读。

`GET /api/shop-settings` 返回来源店铺、销售小组、默认归属及版本。`PUT` 要求站点认证身份、同源 Origin 和预期版本，单条条件写入保证并发冲突返回 409，客户端保留草稿。默认归属不追溯改写已有订单，当前也未将此独立设置绑定为 Base 附加字段或正式订单自动归属。

结构迁移位于 `app/hosted/migrations/0000_shop_settings.sql`，打包时复制到 Site `drizzle/`，由 Sites 发布流程应用。上线不创建或修改 Base 数据。

验证：`node scripts/check-shop-settings.mjs` 使用 SQLite 执行实际迁移和 SQL，覆盖重新读取、清空、改名、来源停用、来源隔离、并发保存和服务端校验。浏览器验证单店/批量保存、页面重载、新浏览器上下文读取、冲突保留草稿、移动端以及首页入口。

已有扩展演示站点使用 `scripts/install-shop-settings-site.py --site-directory <站点目录>` 集成，保留现有演示与 Base 两种模式及生成器。该安装器不替换演示数据；原单快照构建器会拒绝覆盖此类站点。

本次校验中旧 FastAPI 全套测试在首个 TestClient 用例阻塞后停止；该部分代码未改动。受影响的 Worker、设置 SQL、页面浏览器和原扩展演示校验均通过。

修复：线上 Sites 不允许访问 Cloudflare 默认缓存。Base 快照改存 D1，店铺独立同步使用 getOrderSources 并保存到 base_shop_sources；同步不覆盖已有归属。新增同步按钮及非 JSON 错误提示。回归测试模拟默认缓存访问必然抛错的运行环境，验证店铺读取、来源同步、失败保留及归属保留。
